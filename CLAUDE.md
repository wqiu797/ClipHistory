## Build & Run

- **Prerequisite:** `brew install xcodegen` (project generator)
- **Minimum deployment:** macOS 14.0, Swift 6.0

Run commands from the repository root. Build products go to
`${TMPDIR:-/tmp}/cliphistory-derived-data` and are deleted after install/tests,
so Spotlight only keeps the installed copy in `/Applications`.

```bash
# Generate Xcode project (after adding/removing files)
xcodegen generate

# Build, install to /Applications, kill old instance, launch
./build.sh

# Quick debug build only (no install)
DERIVED_DATA="${TMPDIR:-/tmp}/cliphistory-derived-data"
xcodebuild -project ClipHistory.xcodeproj -scheme ClipHistory \
  -configuration Debug -derivedDataPath "$DERIVED_DATA" build

# Run the DAO/database unit tests (also cleans the test host from Spotlight)
./test.sh
```

- `project.yml` is the source of truth for the Xcode project (xcodegen spec)
- Dependencies are declared in `project.yml` and pinned by the Xcode workspace `Package.resolved`
- After adding new Swift files, run `xcodegen generate` to include them in the Xcode project
- `ClipHistory.xcodeproj` is committed but generated; never edit `project.pbxproj` by hand, and commit the regenerated project after running `xcodegen generate`

## Testing

Unit tests live in `Tests/ClipHistoryTests/` and run against an in-memory `DatabaseQueue` migrated with `AppDatabase.migrator`, via `./test.sh`. When XCTest launches the app as its test host, `StatusBarController` skips starting the menu bar item, clipboard monitor and cleanup scheduler.

## Architecture

Menu bar app (LSUIElement = true, no Dock icon) for macOS clipboard history.

**Key patterns:**
- All singletons use `@unchecked Sendable` to satisfy Swift 6 concurrency
- `AppDatabase` wraps GRDB `DatabaseQueue` (SQLite), migrated via GRDB migrator
- `ClipboardMonitor` polls `NSPasteboard.general.changeCount` every 0.5s — there is no push-based clipboard API on macOS. Pasteboard reads happen on the main thread; decoding, hashing, disk and DB writes run on the `captureQueue`.
- Content flagged with `org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType` (password managers) is never captured
- Image dedup uses SHA256 over the normalised PNG; text dedup also SHA256. Hash the PNG, not the raw TIFF, so the same image from different apps still dedupes
- Images are written only after `dao.touch(hash:)` reports a miss — never write files before deduplicating, and never leave files behind if the DB insert fails
- Images stored as PNG files on disk under `~/Library/Application Support/ClipHistory/Images/`; DB stores only filenames. Orphaned files are swept at launch

**Data flow:** `ClipboardMonitor` → `ClipboardItemDAO.touch(hash:)` / `insert` → DB → `ClipboardViewModel.loadItems` (background task) → SwiftUI views

**Critical anti-feedback-loop logic:** When copying back to clipboard, `ClipboardMonitor.markOwnWrite()` must be called AFTER the write, not before. Recording the `changeCount` before the write causes the monitor to capture its own writes.

**Image conversion:** Use `NSImage.tiffRepresentation` → `NSBitmapImageRep(data:)` for saving NSImage to PNG. Using `cgImage` directly loses color data for many NSImage types.

**Settings:** `SettingsWindowController` creates an NSWindow manually (not SwiftUI `Settings` scene) because the `Settings` scene doesn't properly register in a menu-bar-only (no WindowGroup) app.

**Menu bar click handling:** `StatusBarController` uses `button.sendAction(on: [.leftMouseUp, .rightMouseUp])` — left click toggles popover, right click shows context menu with Quit.

**Dependencies:** GRDB.swift (~6.29) for SQLite, KeyboardShortcuts (~2.0) for global hotkey.

## Common Pitfalls

- **Variable name shadowing:** Don't name a local variable the same as a method (e.g., `let pngData = pngData(from: image)` shadows the method, making the second call fail with "cannot call value of non-function type 'Data'").
- **GRDB insert returns Void:** `PersistableRecord.insert` returns `Void` and leaves the value untouched. Use `inserted(_:)` (or `insertAndFetch`) to get the copy whose `didInsert` callback has set the row id.
- **cgImage color loss:** Converting NSImage to PNG via `cgImage` produces transparent images for many NSImage types. Always use `tiffRepresentation` → `NSBitmapImageRep`.
